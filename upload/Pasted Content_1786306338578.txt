# 1. PRIMARY EXECUTION PRINCIPLE

## EXISTENCE ≠ IMPLEMENTATION

This is the most important rule in this entire prompt.

Never consider a feature implemented merely because:

* a file exists;
* a component exists;
* an API route exists;
* a Prisma model exists;
* a database column exists;
* a library is installed;
* an environment variable exists;
* an AI module is imported;
* a boolean is named `encrypted`;
* a mock service exists;
* a provider is configured;
* a UI button exists;
* a feature appears in a menu.

A feature is **IMPLEMENTED** only when it is:

**UI → API → business logic → database/state → external service where required → security controls → error handling → runtime behavior → tests → deployment/runtime verification**

are correctly connected.

Use the following status definitions:

### IMPLEMENTED

Function works end-to-end and has evidence.

### PARTIAL

Some layers exist but the complete user flow does not work.

### MISSING

The capability does not materially exist.

### BLOCKED

Implementation cannot safely continue because an architectural, security, infrastructure, product, or external dependency decision is unresolved.

### DEFERRED

Intentionally postponed by CTO/product decision.

Never convert PARTIAL or BLOCKED into IMPLEMENTED simply because code was written.

# 25. PRIVACY REQUIREMENTS

CIRKLE is privacy-first.

For every feature ask:

1. What personal data is collected?
2. Why?
3. Where is it stored?
4. Who can access it?
5. How long is it retained?
6. Can it remain on-device?
7. Can it be encrypted?
8. Can metadata reveal sensitive information?
9. What happens offline?
10. What happens when the user deletes it?
